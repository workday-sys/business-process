Loan Forgiveness (PSLF Certification)

Initiated by Employee As Self · Primarily a Benefits-side process

StatusHigh Volume of Expected Defects
Who is Involved
  • Employee As Self Initiates & reviews the certification document
  • Benefits Administrator Closes the request
Decision Flags
⚠️
Document Handling Under ReviewCurrently the employee views/receives the certification document but is not required to upload a completed, signed version before moving forward — this may need to change so a completed document is retained on the request.
🛠️
Open Items from Review Session (Expect Multiple Defects) • At some campuses this is not handled by Benefits staff at all — it's treated like an employment-verification process handled by other staff, so the BP may need campus-specific routing.
• The legacy process auto-generates the form and pre-populates employee info; the new flow may need the same instead of a blank upload.
• Request volume is very high.
• Adjunct calculations are significantly more complex — hours vary by semester and require a multiplier to determine PSLF-qualifying full/part-time status, often needing more than one generated document.

Search Exception Request

Initiated by HR Partner · Manager · Management Chain · Requests exception to the standard hiring search

Approvals3–4 Steps
Who is Involved
  • HR Partner / Manager / Mgmt Chain Initiates the request
  • Compensation Partner First approval
  • Recruiting Administrator Second approval
  • Chief Diversity Officer* Approves waiver of minimum requirements (only if requested)
  • HR Administrator Closes the request (comment required)
  • HR Partner To-Do: attaches resolution to Hire/Change Job (only if approved)
Decision Flags
⚠️
Waiver of Minimum Requirements BranchIf the initiator answers "yes" to the waiver question, an extra approval step is inserted before closing. If "no," that step is skipped entirely.
🔀
Conditional To-DoThe final To-Do — attaching the Search Exception Resolution to the Hire/Change Job form — only fires if the request was approved. If denied, there is nothing further to attach.
🛠️
Open Items from Review Session • "Chief Diversity Officer" is a placeholder security group; testers clarified the real approver for a minimum-requirements waiver should be the Chancellor's Office (the CDO has typically already written the supporting letter by this point), so this step is expected to be reassigned.
• Recruiting Administrator and other "administrator" groups may currently be too broad — e.g. central staff outside the campus are also assigned the role and may see confidential search information they shouldn't. Narrower, campus-specific security groups are being scoped.
• Requests for an approval notification/letter to be generated automatically were raised and logged for the notifications workstream.

Transfer Roster List — Competitive & Labor/Non-Competitive Titles

Initiated by Employee As Self · Civil Service workers request transfer to up to 3 campuses

Variants2 — Same Flow, Different Questionnaire
Who is Involved
  • Employee As Self Initiates the request
  • HR Partner Approves the request
  • Civil Service Administrator* Closes the request
Decision Flags
⚠️
Two Request Types, One ProcessCompetitive Titles and Labor/Non-Competitive Titles use the same business process flow — only the questionnaire content differs, since eligibility questions vary by classification.
🔀
Hardship Case BranchIf the request is a hardship case, the employee must confirm a letter with supporting documentation was sent to the union official before proceeding.
🛠️
Open Items from Review Session • The 27 CUNY campuses had to be split into two separate lists (senior colleges / community colleges) because Workday's questionnaire "multiple choice" field type caps out at 25 options — this is a platform limitation, not a design choice, and campuses were asked to flag if any list entries should be removed or consolidated.
• The "select up to 3 campuses" rule is not systematically enforced — testers found they could select more than 3 with no validation, since multi-choice questionnaire fields can't enforce a maximum. This will either need to stay a soft guideline or move to a standard document/form instead of a questionnaire.
• Civil Service Administrator, as the closing group, is considered a likely-too-broad placeholder that will be narrowed down.
• A separate, in-progress goal (not yet built) is a report so each campus can see its own transfer roster directly in Workday instead of using spreadsheets.

Role Definitions
Security role descriptions for Request Frameworks scope
Role Description
Employee / Contingent Worker As Self The worker initiating a request about themselves. Cannot approve their own request.
Manager / Management Chain Listed as an allowed initiator for Search Exception Request alongside HR Partner.
HR Partner Campus-level HR role. Reviews, approves, closes, and receives To-Do steps across most request frameworks. Only role that can initiate Compensation Review.
HR Administrator Central-office-level role (per session clarification). Closes Search Exception Requests and updates the NYSPO custom field. Naming may change so campuses don't assume it's central-only by default.
HR Specialist Receives the To-Do step to review type of assistance on Emergency Evacuation Assistance requests. Distinct from HR Partner.
Civil Service Administrator Reviews/approves 55-a Status and closes Transfer Roster List requests. Currently a placeholder in several flows pending security mapping (vs. "Civil Service Director").
Benefits Administrator Closes Loan Forgiveness requests. Session noted this doesn't map cleanly to every campus's actual process owner.
Compensation Partner First approval step on Search Exception Request.
Recruiting Administrator Second approval step on Search Exception Request. Session flagged this group as potentially too broad (includes central staff outside the requesting campus).
Chief Diversity Officer Placeholder security group for the conditional waiver-of-minimum-requirements approval on Search Exception Request. Real approver expected to be the Chancellor's Office.
Integration (system) Automated background step — not a person. Used on FICA Exempt Status (outbound to Campus Solutions) and NYSPO Account Activation (communicates with NYSPO/State).
